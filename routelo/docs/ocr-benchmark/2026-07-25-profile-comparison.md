# RouteLO PP-OCR 오프라인 프로파일 비교 (2026-07-25)

## 목적 (#99)
기기 없이 8장 골든 영수증에 **현재 프로덕션 파이프라인**을 돌려 두 전처리
프로파일의 문자 정확도(CER)를 비교한다. `stable-mobile`(현재 기본)과
`high-res-preprocess`(#91에서 추가됐으나 실측 판정이 밀려 있던 프로파일) 중
무엇을 기본으로 둘지 데이터로 판정하기 위함.

## 러너
`benchmarks/ocr/receipt-samples/scripts/run-routelo-ppocr.mjs`
(`npm run routelo:run -- --profile <id>`)

- 앱과 **동일한 ONNX 모델·한국어 사전**을 사용.
- DB 후처리·원근 워프·CTC 디코딩(NFC 포함)은 **프로덕션 TS 모듈을 그대로 import**
  한다(재구현하면 측정값이 앱과 달라진다). `onnxruntime-node`로 실행.
- 유일한 차이: 이미지 디코드/리사이즈. 앱은 네이티브 `expo-image-manipulator`를
  쓰지만 Node에는 없어 `jpeg-js` + 순수 JS 이중선형 리사이즈로 대체한다. 두
  프로파일에 **동일하게** 적용되므로 프로파일 간 비교에는 영향이 없다.
- 평가는 기존 `scripts/evaluate-text-candidate.mjs`(정규화 CER) 재사용.

## 결과

| 지표 | stable-mobile (기본) | high-res-preprocess | 변화 |
|---|---|---|---|
| 정규화 CER (낮을수록 좋음) | 0.8807 | **0.7944** | -0.0863 (상대 9.8%↓) |
| 평균 토큰 커버리지 (높을수록 좋음) | 0.1977 | **0.3147** | +0.1170 (상대 59%↑) |
| 빈 결과율 | 0.0000 | 0.0000 | 변화 없음 |
| 이미지별 CER 승패 | — | 5승 / 2패 / 1무 | high-res 우세 |

프로파일 파라미터: `stable-mobile` detectorMaxSide=960 / recWidth=320 /
minConf=0.35, `high-res-preprocess` detectorMaxSide=1536 / recWidth=480 /
minConf=0.48 + 조명 정규화.

## 해석
1. **해상도가 병목이다.** 검출기 입력을 960→1536px로 올린 것만으로 토큰
   커버리지가 59% 상승했고, 최소 신뢰도를 0.35→0.48로 **더 엄격하게** 했음에도
   이겼다(오탐 증가가 아니라 실제 인식 향상). #84의 P0-D(960px에서 작은 한글
   손실) 가설이 데이터로 확인됨.
2. **그래도 ML Kit보다 약하다.** ML Kit 한국어 베이스라인은 CER 0.6173 /
   커버리지 0.8468(#106, 네이티브 실측). high-res로도 격차가 크다.

## 주의
- 이 러너의 이미지 리사이즈는 앱의 네이티브 경로와 달라 **절대 CER은 실기기와
  다를 수 있다.** 두 프로파일 비교(동일 러너)는 공정하지만, ML Kit 네이티브
  수치와의 직접 비교는 참고용이다.
- 최종 판정은 갤럭시 실기기에서 같은 영수증으로 두 프로파일을 비교해 확정한다.
