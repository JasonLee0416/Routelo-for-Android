# 장소 사전(venue gazetteer) 출처 감사 (#149)

## 왜 필요한가 (법적 근거)

장례식장·예식장 사전(`app/ocr/venue/metro-venues.json`)이 담는 **상호 + 사업장 주소**는
법인·사업장 정보이므로 **개인정보보호법의 개인정보에 해당하지 않는다**(행안부·개인정보보호위원회
「개인정보 보호법」 해설서). 따라서 이 데이터를 앱에 담아 배포하는 것 자체는 개인정보보호법상
원칙적으로 문제되지 않는다.

실제 법적 리스크는 **데이터의 출처**에 있다.

- **저작권법 제93조(데이터베이스제작자의 권리)**: 타인이 상당한 투자로 구축한 DB의 전부/상당
  부분을 복제·배포하면 침해. 개별 항목이라도 **반복적·체계적으로 복제**하면 "상당한 부분"으로
  간주(제93조 제2항). 웹 크롤링 수집의 대표 판례: 대법원 2022. 5. 12. 선고 2021도1533.
- **부정경쟁방지법 (파)목**: 타인의 상당한 투자·노력의 성과를 공정한 거래질서에 반해 무단 사용.
- **지도서비스 이용약관**: 네이버지도·카카오맵 등의 검색·지오코딩 결과를 **영구 저장·DB화·재배포**
  하는 것을 대개 금지.

즉, 같은 "상호+주소" 사실정보라도 **어디서 모았는지**에 따라 배포 안전성이 갈린다.

## 현재 상태

- 스키마에 `source`(provenance) 필드를 추가했다. 값: `localdata` | `public-mohw` |
  `self-collected` | `map-suspect` | `unverified`.
- 기존 768건(서울/경기/인천 장례식장·예식장)은 원 출처가 문서화되어 있지 않아 전부
  `unverified`로 표기했다. → **배포 안전 0건, 재수집 대상 768건.**
- 리포트: `npm run venue:provenance`.

> 주의: `unverified`는 "위법 확정"이 아니라 "출처 미확인"이다. 다만 지도서비스 유래가 섞여 있을
> 가능성을 배제할 수 없으므로, 배포 안전을 확보하려면 아래 계획대로 공공출처로 승격해야 한다.

## 재수집·승격 계획 (#150 연계)

1. **공공데이터로 재구축**: 지방행정 인허가데이터(구 LOCALDATA → data.go.kr 통합)의
   **예식장업 / 장례식장(장사시설)** 인허가 목록, 보건복지부 e하늘·지자체 장사시설,
   공공데이터포털 "전국장례식장" 데이터셋. 공공누리 라이선스(유형 확인: 제1유형=상용 OK,
   제4유형=상용 금지).
2. **교차검증**: 기존 사전을 공공데이터와 **주소/전화 기준**으로 대조.
   - 공공데이터에서 일치 → `source`를 `localdata`/`public-mohw`로 승격.
   - 공공데이터에 없고 지도서비스 유래가 의심되면 → `map-suspect`로 표기하고 **재수집 또는 제거**.
3. **좌표 보강**: 행정안전부 도로명주소/좌표 API.
4. **출처표시**: 공공누리 요건에 따라 앱/문서에 출처 표기.

## 무결성 원칙

- 이 감사·재수집 작업은 **런타임 매칭 동작을 바꾸지 않는다**. 매칭은 기존대로 비파괴·review-only
  (사용자가 후보를 탭할 때만 값 반영, zero-fabrication 유지).
- 배포 전 각 데이터셋의 라이선스·약관과 함께 법률 전문가 최종 검토를 권장한다.
