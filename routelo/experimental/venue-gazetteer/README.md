# 실험: 장소 가제티어(Venue Gazetteer) — OCR 상호명/배송지 보강

> ⚠️ **실험 영역 (experimental) — 프로덕션 병합 금지.**
> 이 디렉터리는 실험적 아이디어를 검증하기 위한 격리 공간이다. `app/` 런타임에
> import 되지 않으며, CI 게이트/제품 동작에 영향을 주지 않는다. 검증이 끝나면
> 별도 판단 후에만 프로덕션 편입을 논의한다.

## 아이디어
서울시(1차)·경기도(2차) 소재의 **장례식장·예식장 상호명 사전**을 앱에 내장하고,
OCR로 뽑힌 배송지/상호명 텍스트를 이 사전과 대조한다. 부분 일치(핵심 토큰 몇
글자)라도 강하게 걸리면, 해당 장소를 **후보로 제시**해 인식 확신도를 높인다.

실제 인수증의 배송지는 "고대구로병원 장례식장 105호실", "공군호텔 그랜드볼룸"
처럼 **알려진 장소명 + 호실/층** 형태가 많다. OCR이 장소명 일부만 맞혀도 사전
매칭으로 정규 명칭을 복원할 수 있다.

## zero-fabrication 원칙 유지
매칭 결과는 **자동 확정하지 않는다**. 후보(alternatives)로만 노출하고 사용자가
검토·선택한다. 낮은 유사도의 오매칭이 신뢰 데이터(라우팅/요금)로 새지 않도록
임계값을 보수적으로 둔다.

## 데이터 스키마 (`data/*.json`)
각 항목:
```json
{
  "name": "고려대학교구로병원 장례식장",   // 정규 명칭
  "aliases": ["고대구로병원 장례식장", "구로병원 장례식장", "고대구로 장례식장"],
  "district": "구로구",                     // 서울 자치구
  "address": "서울 구로구 구로동로 148",     // 확인된 도로명(없으면 "")
  "type": "funeral"                          // "funeral" | "wedding"
}
```

파일:
- `data/seoul-funeral.json` — 서울 장례식장
- `data/seoul-wedding.json` — 서울 예식장/웨딩홀
- (2차) `data/gyeonggi-*.json`

## 매칭 설계 (`venueGazetteer.ts`)
1. 정규화: 공백/구두점 제거, 소문자화, 호실/층/번지 등 꼬리 제거.
2. 후보 생성: 각 항목의 `name`+`aliases`를 정규화해 인덱싱.
3. 점수화: OCR 토큰과 사전 항목 간
   - 최장 공통 부분문자열(LCS) 길이 / 짧은 쪽 길이 비율
   - 핵심 토큰(병원명·예식장명) n-gram 겹침
   를 결합해 0~1 유사도 산출.
4. 임계값 이상만 후보로 반환(정렬). 1~2글자 우연 일치는 최소 길이 가드로 배제.

## 검증 계획
- 골든 8장의 배송지 원문(교원예움 서서울 장례식장, 고대구로병원 장례식장,
  중앙대병원 장례식장, 보라매병원, 공군호텔 등)으로 매칭 재현율/오탐 측정.
- 실기기 ML Kit 원문(오탈자 포함)에 대한 강건성 확인.

## 상태 (수도권 전역 완료)
- [완료] **서울** 장례식장 63 + 예식장 265 = **328곳**(사용자 판정 정밀 dedup)
- [완료] **경기도** 장례식장 183 + 예식장 182 = **365곳**(30개 시·군)
- [완료] **인천** 장례식장 35 + 예식장 40 = **75곳**(10개 구·군, 2026-07 행정개편 신명칭)
- [완료] **수도권 총 768곳** (`data/{seoul,gyeonggi,incheon}-*.json`)
- [완료] 매칭 모듈 + 오프라인 검증 (총 18 테스트, 골든/경기/인천 배송지 매칭)
- [예정] 프로덕션 파이프라인 연동 실험(venueName/deliveryAddress 후보 주입, review only)
- [예정] 프로덕션 파이프라인 연동 실험(venueName/deliveryAddress 후보 주입, review only)
- [보류] 프로덕션 편입 여부(실험 결과에 따라 별도 결정 — 현재 미병합)

### 데이터 출처·병합
1차 자체 수집(KFCPI 장례식장 + 웨딩포털)에 사용자 제공 Codex 데이터(소상공인시장진흥공단
상가정보 + 보건복지부 장례식장 현황 + 카카오맵 대조)를 병합. 정규화 이름 기준 중복
제거·별칭 union. `tier`로 검증 수준을 구분해 **미확인 장소도 포함**(사용자 요청):

| type | 계 | primary(지도·공공 확인) | additional_candidate | public_unresolved(지도 미대조) | registry(KFCPI만) |
|---|--:|--:|--:|--:|--:|
| funeral | 73 | 61 | – | – | 12 |
| wedding | 272 | 226 | 4 | 42 | – |

### 검증 요약 (실데이터, 병합 후)
| 유형 | 골든/샘플 배송지 매칭 |
|---|---|
| 장례식장 | 중앙대·고대구로·보라매·교원예움서서울 등 5건 score 1.00 |
| 예식장 | 더채플앳청담·콘래드서울·롯데호텔월드·신라호텔 score 1.00 |
| 예식장(신규 커버) | **공군호텔 웨딩홀·해군호텔 W웨딩홀**(골든 base/IMG_01) 0.80 — Codex 병합으로 확보 |

매칭 정규화: 호실/층 + 일반 홀·연회장·예식 종류어(그랜드볼룸/크리스탈볼룸/웨딩홀 등)
제거로 장소명 핵심만 비교(장례식장은 보존). 오탐: 무관 텍스트 0건. `tier` 필터로
확인된 장소만 우선 매칭하는 운영도 가능.
